# 給 GARCH 再加一層神經網路，為什麼預測反而更差？K426 的教訓

很多人對波動率預測有一個很自然的想法：既然 `GARCH` 已經能抓到波動叢聚，那再丟進一層神經網路，理論上應該只會更好。

`K426` 做的，就是把這個直覺拿去碰硬資料。

它不是在比一個慢吞吞、寫得很亂的 prototype。相反地，這次特地把舊版 `K419` 的效率問題先修掉：`GARCH` 不再每天重估，改成每 `21` 天重估一次；神經網路也不用 `LSTM`，改成更輕的 `MLP`；整個實驗在 `1.5` 秒內就跑完。

換句話說，`K426` 測的不是「程式有沒有太慢」，而是更直接的一題：

**在日頻 `SPY` 波動率預測上，把 `GARCH` 特徵交給機器學習再修正一次，到底有沒有實際幫助？**

答案很乾脆：沒有。這次不只沒贏，還輸得很明顯。

## 先看結果：老模型一個人就夠了

`K426` 的外樣本區間是 `2023-01-01` 到 `2024-12-31`，共 `502` 個交易日。比較對象有三個：

- `GJR-GARCH`
- `GINN-MLP`
- `GINN-Ridge`

其中 `GINN` 的想法是：先用 `GARCH` 萃取波動資訊，再把那些特徵丟給機器學習模型，看看能不能學到額外修正。

結果如下：

![K426 三模型 QLIKE / MSE 比較](experiments/k426/k426_general_model_comparison.png)

最重要的是 `QLIKE`，因為這是波動率預測裡常用、也相對穩健的 loss。

- `GJR-GARCH QLIKE = 0.5686`
- `GINN-MLP QLIKE = 7.5653`
- `GINN-Ridge QLIKE = 103.9089`

這個落差不是小輸，是很大的退步。

`GINN-MLP` 比 `GJR-GARCH` 差了 `1230.4%`，`GINN-Ridge` 更差到 `18173.4%`。如果只看 `MSE`，神經網路和 `Ridge` 也都沒有占到便宜。

這裡最有價值的地方，在於它打掉了一個常見幻覺：**模型更複雜，不代表預測更準。**

在日資料頻率上，波動率本來就沒有那麼多可榨的訊號。你把 `28` 個特徵、兩層 `MLP`、標準化、early stopping 全部堆上去，最後學到的可能只是更多噪音。

## 它有沒有偷看未來？這次沒有

遇到這種「機器學習大幅輸給簡單模型」的結果，第一個要問的通常不是結論對不對，而是實驗有沒有做乾淨。

`K426` 這次最重要的防呆，是把所有特徵都明確 lag 到 `t-1` 以前。

腳本裡列出的 `28` 個特徵，包含：

- 過去報酬 lag
- 過去平方報酬
- 絕對報酬
- `5/10/21/63` 日滾動波動
- 槓桿效應 proxy
- volume 變化
- `GARCH` 條件變異數相關特徵

而且每一項都要求至少 `shift(1)`。也就是說，模型在預測今天的 `RV_t = r_t^2` 時，只能看到昨天收盤以前已知的資訊。

這點很重要，因為很多機器學習版本的波動率實驗，最後看起來表現很好，真正原因只是把當日資訊不小心混了進去。`K426` 這次刻意把那條路堵死，剩下的結果才有解讀價值。

## 為什麼神經網路會輸成這樣

這篇實驗最值得一般讀者記住的，不是某個架構名稱，而是背後的機制。

日頻波動率資料有一個很煩的特性：

- 訊號弱
- 雜訊高
- 樣本不算大
- 真正穩定的結構，其實已經被 `GARCH` 類模型抓走不少

在這種環境下，機器學習很容易遇到兩個問題。

第一個問題是 **overfit**。

`MLP` 在訓練資料上可以找到一些看似有用的組合，但一到外樣本，這些關係就鬆掉了。`K426` 的 `GINN-MLP` 只跑了 `25` 次 iteration，訓練時間也只有 `0.07` 秒，代表它不是算不動，而是算得動也沒學到穩定增量。

第二個問題是 **特徵冗餘**。

如果 `GARCH` 已經把波動叢聚和槓桿效應濃縮得差不多了，後面的 `MLP` 很可能只是在舊訊號上再做一次變形。那不是增加資訊，而是增加自由度。

從結果看，這個解釋很合理。因為 `prediction correlation` 也沒有改善：

- `GJR-GARCH` 的 `Spearman rho = 0.2101`
- `GINN-MLP` 只有 `0.1673`
- `GINN-Ridge` 是 `0.1971`

模型變複雜，排序能力反而更差。

## 特徵重要度也透露出一件事

`MLP` 最前面的特徵，幾乎都還是很傳統的波動 proxy。

![K426 MLP Top 10 特徵重要度](experiments/k426/k426_general_feature_importance.png)

前幾名包括：

- `rstd_5d_lag1`
- `rv_lag2`
- `rmean_abs_5d_lag1`
- `rmean_abs_21d_lag1`

看到這裡，其實有點像在看一個誠實版的答案卷。

機器學習模型被給了 `28` 個特徵，最後最常用的，還是那些最接近「短期已實現波動」的老東西。它沒有神奇挖出什麼全新結構，也沒有從 `GARCH` 特徵裡抽出特別強的非線性修正。

這種結果通常代表一件事：**資料裡真正穩定的訊號很簡單，額外的複雜度只是把邊角噪音放大。**

## 這和先前的「QLIKE 天花板」文章有什麼不同

平台之前已經有一篇比較大的綜述文章，談的是日頻 `QLIKE ceiling`：很多看起來比 `GARCH` 更聰明的模型，最後都沒能穩定突破那條線。

`K426` 的價值，不在於再把大結論講一遍，而是補上一個非常具體的個案：

**當你把「GARCH 特徵 + 神經網路修正」這套常見 ML 直覺，真的用乾淨、快速、可重跑的方式做出來，結果仍然是輸。**

所以這篇比較像一個現場示範。

它告訴你，日頻波動率預測裡最危險的，不一定是模型太弱，而是研究者太容易把「架構更新」誤當成「資訊更多」。

## 一般投資人可以帶走什麼

如果你不是做學術研究，而是比較關心實務，那 `K426` 至少有三個可用的提醒。

第一，看到「AI + 金融」不要先把效果預設成升級。

金融資料的可預測性本來就有限。模型加得越多，越可能只是把資料中的偶然模式背下來。

第二，日頻環境下，老模型常常不是因為保守才留下來，而是因為它真的已經很接近可用上限。

第三，若真的要期待機器學習發揮，關鍵可能不在「神經網路夠不夠深」，而在 **資料本身有沒有新增真正不同的資訊**。例如更高頻的 realized volatility、選擇權面資料，或跨市場 order flow。單靠日線 lag 特徵，多半不夠。

## K426 的一句話結論

`K426` 給的不是一個酷炫成功故事，而是一個很有用的煞車：

**在 `SPY` 的日頻波動率預測上，把 `GARCH` 特徵丟進神經網路，至少在這次乾淨重測裡，沒有創造額外 alpha，反而把預測弄得更差。**

這種 NULL result 不熱血，但很值錢。因為它幫研究者少走很多看起來先進、其實沒有新增資訊的路。
