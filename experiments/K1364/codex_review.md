## Findings

No source-level blocker found for the reported `NULL_PROXY` result.

The script uses explicit lagged information for the predictive variables:

```python
log_adv_lag1 = np.log1p(dollar_volume).rolling(...).mean().shift(1)
etf_shock_lag1 = etf_shock_raw.shift(1)
```

The target variables are realized on day `t`; the ETF shock, volume shock, tracking-error shock, liquidity ranking, ETF absolute return control, market RV control, and lagged dependent variable all use information available through `t-1`.

## Checks

- `SEED = 42` is fixed and used for bootstrap sampling.
- `K1364_results.json` is generated by `K1364.py`, not hand-filled.
- The script writes the derived regression panel to `K1364_panel.csv`, making the JSON coefficients traceable.
- Formal inference uses cluster-by-date standard errors and Bonferroni adjustment across three targets.
- The README conclusion matches the JSON: all coefficients are directionally positive, but no target clears the Bonferroni gate and all event CIs cross zero.

## Caveats

- This is a free-data proxy, not direct AP creation-redemption basket evidence.
- yfinance holdings are current top-10 snapshots; historical holdings drift and survivorship bias are material limitations.
- Tracking error is measured against a normalized top-10 holdings basket, not official NAV.
- Daily OHLCV cannot identify intraday arbitrage trades, quoted depth, or official bid-ask dynamics.
- Cluster-by-date standard errors handle common daily shocks but do not turn the design into causal identification.

## Allowed Knowledge Claim

K1364 supports only the narrow null finding that this yfinance top-holdings / daily-price proxy does not robustly detect stronger post-shock RV, market-beta-proxy, or ETF-comovement responses among high-liquidity constituents. It should not be cited as evidence against the JFQA ETF sampling-arbitrage mechanism.
