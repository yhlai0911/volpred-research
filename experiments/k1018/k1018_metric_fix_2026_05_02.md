# K1018 Metric Helper Fix — 2026-05-02

## Background

Codex review of mile_a4311ba7 (K1018 published article) flagged 3 source-level
issues in `experiments/k1018/k1018.py` `compute_metrics()` + `dm_test()`:

1. MDD used arithmetic-cumulative `np.cumsum(r)` then computed dd as raw level
   diff (not relative-to-peak fraction).
2. CAGR used arithmetic `np.sum(r)` for total return rather than compound
   `np.prod(1+r)-1`.
3. `dm_test()` used squared-returns difference as DM loss — measures realized
   variance, not predictive accuracy; non-standard for strategy-vs-strategy
   comparison.

Article prose was patched at publish time (mile_a4311ba7 footnote);
this is the root-cause source fix.

## Diff Summary (k1018.py)

### `compute_metrics()` lines 307-319
- `cum = np.cumsum(r)` → `cum = np.cumprod(1 + r)` (compound NAV path)
- `dd = cum - peak` → `dd = (cum - peak) / peak` (relative drawdown)
- `total_r = np.sum(r)` → `total_r = np.prod(1 + r) - 1` (compound total return)

### `dm_test()` lines 351-389
- Replaced squared-returns "loss" with **Newey-West-corrected mean-return-
  difference t-test**:
  - `d = r1 - r2` (raw return diff, not squared)
  - Long-run variance via Bartlett kernel weights `w_k = 1 - k/h`
  - Function name retained for API-compat; comment notes downstream readers
    should interpret t_stat as mean-diff t-stat, not classical DM forecast-loss
    statistic.
- For h=1 (default in K1018) reduces to iid-corrected mean-diff t-test, which
  is what most strategy comparison papers report.
- Newey-West weights are now Bartlett (decreasing) rather than uniform — the
  prior code computed unweighted γ_k sum which over-counts long lags.

### Direction of change (matches prediction in brief)

- **Sharpe**: unchanged across all rows (mean / std unaffected by helper bug — confirms hypothesis).
- **CAGR**: increased ~5 pp (≈80% relative) for all rows. Counter-intuitive
  vs brief's prediction ("compound < arithmetic sum"), but explanation is:
  the buggy `total_r = np.sum(r)` summed daily returns and then plugged that
  *small* sum into `(1 + total_r)^(1/n_years) - 1`. Over 5098 days the daily
  sum is bounded by drift and **less than** the compound product, so old
  CAGR was actually understated — the bug was MDD-pessimistic but
  CAGR-pessimistic too. New CAGR ≈ true geometric mean annualized.
- **MDD**: |MDD| **decreased** ~4 pp (e.g. robust_vt_weekly -35.55% → -31.26%).
  Counter-intuitive vs brief's prediction ("compound dd more extreme"). Reason:
  the old code computed `dd = cum - peak` where `cum` was an arithmetic-sum
  level. Since arithmetic sum has unbounded growth (no compounding cap), the
  level-diff drawdown was inflated relative to a NAV-fraction drawdown. The
  fix correctly normalizes by peak NAV → less extreme % drawdown.
- **Calmar**: ~doubled (CAGR ↑ + |MDD| ↓ → strong combined effect). All
  numbers now consistent with industry standard (NAV-path-based Calmar).
- **bh_spy MDD**: -70% → -55.19%. The 2008 SPY peak-to-trough drawdown is
  historically ~55% (S&P 500 close-to-close 2007-10-09 to 2009-03-09). New
  number matches reality; old -70% was an arithmetic-sum artifact.

(robust_vt vs baseline 12/VIX no statistical edge; bh_5050 dominates on Sharpe).
