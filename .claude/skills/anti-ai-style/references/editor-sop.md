# 編輯審核 SOP — 3 階段、9 必跑 checklist

寫稿完成後（自己寫或 AI 生）publish 前必跑。不准跳階段。
單一階段失敗即回頭修，全 9 項 PASS 才能 publish。

---

## 階段一：邏輯與結構初審（拆假骨架）

**目的**：先確認文章「骨架」不是 AI 套路。骨架歪了，後面修語法都救不回來。
**預估時間**：5-10 分鐘 / 1000 字。

### Check 1.1 — 「不是…而是…」掃描

```bash
grep -nE "不是.*而是|不只是.*而是|並非.*而是" $DRAFT
```

- [ ] 結果為空？✓ pass
- [ ] 有命中？→ 逐句改寫成直接肯定（範例：「不是 X 而是 Y」→「核心在 Y」）
- [ ] 改寫後再 grep 確認空

**例外允許**：學術論文中對兩個 well-defined 概念做嚴格 contrast（如「Type-I error 不是 Type-II error」）— 但本平台 feed 文章不允許。

### Check 1.2 — 結論爆米花式擴張

對每段最後 2 句問：
- [ ] 結論的「大道理」是否超出本段證據能支撐的範圍？
- [ ] 若拿掉結尾的昇華句，本段論點是否仍站得住？
  - 是 → 拿掉結尾昇華句
  - 否 → 重寫結尾，讓它**只**講本段證據能支撐的小結論

範例：
- ❌ 「資料顯示 SPY Sharpe 1.3 — 這揭示了人類對風險的本質性錯誤認知。」
- ✓ 「資料顯示 SPY Sharpe 1.3 — 過去 5 年高於 60/40 portfolio 的 0.9。」

### Check 1.3 — 稻草人 / 無 source claim

```bash
grep -nE "有人說|不少人認為|坊間流傳|常聽到|數據顯示|研究指出|專家分析" $DRAFT
```

- [ ] 每一個命中句必附 primary source URL / DOI / 文獻 citation
- [ ] 無法附 → 整句刪除（不可改成「一般而言」搪塞）
- [ ] 已附 → 跨模型驗證 source 真實性

---

## 階段二：資訊密度與語法去油膩（修壞肉）

**目的**：句子層面修剪。骨架對了，這階段把每句的肉修瘦。
**預估時間**：15-30 分鐘 / 1000 字。

### Check 2.1 — 逐句新資訊測試

對文章每一句問：「拿掉這句，讀者會缺哪個新事實 / 新推論 / 新例子？」

- [ ] 答得出 → ✓ keep
- [ ] 答不出 → 合併到上下句 OR 刪
- [ ] 連續 ≥3 句答不出 → 整段重寫

執行細節：
- 用編輯器跑 markdown preview 一次看一段，逐句評
- 寫長文時 hardest — 預計 1000 字至少要 cut 200-300 字

### Check 2.2 — 戲劇感轉折詞配額

```bash
grep -cE "然而|真正的考驗|事實上|但其實|悲劇|命運的轉折" $DRAFT
```

- [ ] 全文「然而」≤2 次
- [ ] 全文「真正的」≤1 次
- [ ] 全文「事實上」「但其實」共 ≤1 次
- [ ] 「悲劇」「命運的轉折」=0
- [ ] 超標 → 拔掉，讓敘事依邏輯自然流動（直接接下個動作 / 數字 / 結論）

### Check 2.3 — 翻譯腔 / 吊書袋

```bash
echo "翻譯腔「這」每 200 字密度:"
WORD_COUNT=$(wc -m < $DRAFT)
THIS_COUNT=$(grep -cE "這讓人|這使得|這意味著|這代表" $DRAFT)
echo "  ratio = $THIS_COUNT / ($WORD_COUNT / 200) per-200char"

echo "吊書袋:"
grep -nE "結構性|本質上是|深層次|多維度|生態化|賦能|閉環" $DRAFT
```

- [ ] 「這讓人 / 這使得 / 這意味著」密度 ≤3 個每 200 字
- [ ] 吊書袋詞每命中一個 → 替換 "東西" 測試：句子仍通順 = 純裝飾 → 刪
- [ ] 替換後不通 = 該詞有實質意義 → keep but rewrite 用更具體詞

## 階段三：事實查核與情感注入（注入靈魂）

**目的**：最後一道防線，把 AI 看不出來的問題抓出來。
**預估時間**：10-20 分鐘 / 1000 字 + Gemini round-trip 時間。

### Check 3.1 — 跨模型事實查證

對所有 citation / 數字 / 名言：

```bash
# 提取所有 claim
grep -nE "[0-9]+%|根據|研究|論文|報告|引用|曾說" $DRAFT > /tmp/claims.txt

# 跨模型驗證
cat /tmp/claims.txt | gemini -m gemini-2.5-pro -p - -y --skip-trust <<'EOF'
請逐項驗證下列 claims：
(1) 數字 / 統計是否真實？給 primary source URL
(2) 名人語錄是否確有其事？給原始出處
(3) 研究 / paper 是否真實？給 DOI

對每項標：VERIFIED / SUSPICIOUS / FABRICATED
EOF
```

- [ ] 所有 VERIFIED → keep
- [ ] SUSPICIOUS → 自己加查 primary source 確認；確認不過 → 刪
- [ ] FABRICATED → 立刻整句刪 + 文中相關推論一併重審

### Check 3.2 — 情緒命名 → 畫面轉化

```bash
grep -nE "讓人感到|不禁|油然而生|突然覺得|心酸|孤獨|拋棄|震撼|無力|絕望|感動|釋懷" $DRAFT
```

對每個命中：
- [ ] 改寫為**具體畫面 / 動作 / 感官細節**
- [ ] 留白給讀者自己連結情緒（不替讀者下結論）

範例：
- ❌ 「看著母親老去的背影，讓人不禁感到心酸。」
- ✓ 「母親伸手扶牆停了三秒，髮根的白比上週更深一寸。」（讀者自己感到心酸，不寫出來）

### Check 3.3 — 人味與溫度

讀一遍全文，問三個問題：
- [ ] 本文是否有「只有這個作者能寫」的個人觀點 / 切角 / 經驗？
  - 沒有 → 加一段第一人稱 / 個案經驗 / 對 K-experiment 的反思
- [ ] 本文是否帶批判性思考（質疑 mainstream narrative / 文獻 / 數據）？
  - 沒有 → 加 1-2 句質疑或補充視角
- [ ] 本文若由 LLM 重新生成，能否得到「相同的個人色彩」？
  - 能 → fail，必加更具體的個人 anchor
  - 不能 → ✓ pass

## 快速版（時間壓力下）

只有 30 分鐘：
1. 跑 Check 1.1（不是…而是）+ Check 1.3（稻草人）— 邏輯先正
2. 跑 Check 2.1（新資訊測試）抽樣 5 段
3. 跑 Check 3.1（事實查核）對所有 citation

跳 2.2、2.3、3.2、3.3 — 但下次 update_history 必須補跑。

---

## 失敗 escalation

若同一篇文章連續 2 輪 SOP 仍卡關（同一 check 反覆 fail）：
- → 整篇重寫（不要繼續修補）
- → 重寫時用更嚴格的 prompt-templates.md 原則 1（角色降到國一）
- → 第 3 輪仍 fail → 該主題暫停，另選 topic

寫不出沒 AI 味的版本 → 證明 topic 對該作者 / AI 太硬；強推會踩 mission Goal 1（文章品質）+ Goal 5（曝光）兩條線。
