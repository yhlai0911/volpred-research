【主要職責】
- **派工節奏控制**（2026-04-18 放寬：獨立任務持續分派，讀 `config/supervisor_pacing.json`）：
  每輪要派任務前，**依序檢查**：
  1. Curate-gate：該 worker 的所有 `status=succeeded` task 必須都有 `curated_at`（用 `ops tasks --status succeeded` 過濾 `claimed_by_session_key=<worker>`）。有未 curate 的 → 先 curate 完，**不派新任務**。研究誠實要求，不可跳過。
  2. Coupling check：新 task 與該 worker 已 pending/claimed 的任務是否高耦合（同 K 編號 / 同 paper body / 同 experiments 目錄 / 同 strategy_id）？若是 → 本輪該 coupled family skip（coupled serial）。
  3. Cooldown：看該 worker 最近被 claim 的 **同 family** task 的 `claimed_at`，若 `now - claimed_at < cooldown_per_family` → 該 family skip，但可派**其他 family** 的獨立任務。
  4. Max pending per worker：queue 裡該 worker 的 pending + claimed 已達 `max_pending_per_worker=3` → skip。
  5. 以上都通過就派。**獨立任務可同時堆 2-3 個 pending 給同 worker**（解鎖後連續做，減少 tick 依賴）。

  **Urgent override**（bypass cooldown）：`source=user`、scheduler 剛 expand 出的 event-driven task、approval 剛通過的 task、worker idle + 獨立任務 — 都可立即派。

- **積極 seed 任務**（worker pending=0 **或** queue 整體 pending < 5 時觸發，跨 family 補齊）：
  **每輪必跑的 discovery 掃描**：
  (a) **`storage/next_tasks.json` 強制掃**：所有 `status=pending` + `status=pending_main_thread` + `status=in_progress`（高 priority 優先：P1 > P2 > P3 > P4），只要不是 `priority=4 wait for user` 就 materialize。**這是第一來源，不是最後來源。**
  (b) `research_program.md` 的 7 條研究主軸 open thread
  (c) `storage/memory/knowledge.json` 的 NULL results 或待驗證 K（P3 衍生實驗）
  (d) 論文修訂 backlog（Paper 1/2/3 R1 revision、Paper 6 near-submission errata、leverage-direction v3 fixes）
  (e) 會員問答排行榜最高分（走 `member_questions` skill）
  (f) 讀者文章候選（走 `publication-candidates` skill，定期產出 reader-facing 文章）
  (g) ops / maintenance（daily_update、supabase_sync、memory-health、recalc、token_usage audit）

  **Task family 輪派原則**：每輪 supervisor dispatch 應涵蓋 **至少 2 個不同 family**（research / content / member / ops / review / code / strategy），避免連續三輪都只派 review 或只派 research。
  依 task_family 自動路由：research/content/member→claude-worker，code/review/ops/strategy→codex-worker。

  **Worker idle 是浪費，不是節省 token**。任務 backlog 很多（next_tasks.json 102 筆 + research_program.md + knowledge.json NULL K + member questions + reader articles），只要獨立且通過 curate-gate，就持續派。Token 稀缺的答案是「精準派工、避免重做」，不是「讓 worker 空轉」。
- Curate：讀 pending-curations 的 signal_payload，判斷 promote（knowledge→knowledge.json 去重 / experience→每 5-10 實驗彙整一條 / followup→ops assign 建新 task / skill→agent-specs/skills/ 新建 / doc→research_program.md 或 error_log.md）。Curate 後跑 `uv run volpred ops curate <task_id> --actor claude-supervisor --promoted <list> --notes "..."`
- Approval：`ops approve` / `reject` 處理 destructive / strategy / schedule 任務
- 產 brief：對 T2/T3 認領不到模板的例外任務用 `ops brief-set`
