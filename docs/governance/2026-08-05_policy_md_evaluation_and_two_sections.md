### 1.3 結論：省的方法不是刪字，是**按角色渲染**

**沒有任何一節可以在不改變行為的前提下縮成 pointer。** 每一節都有人依它決定下一個動作。
把規則縮成「詳見 X」只是把載入成本挪到 X，而且多一次 round trip——
對一個**必讀**的規則書，pointer 是純虧。

真正的浪費不是文字長度，是**每個角色都讀到不屬於自己的段落**。
機制已經存在：`build_brief()` 與 `build_manager_brief()` 本來就是兩條路徑。

**建議（不刪一條規則）**：

| 段落 | 條件 | 對誰省 | bytes |
|---|---|---|---:|
| computer use 全節 | 僅渲染給 registry `capabilities` 含 `computer_use` 的角色 | 其餘 7 個角色 | 1,282 |
| 決策鏈的經理側 3 條（「經理全權決策」「只有非常重大…提案」「不確定算不算重大的判準」） | 僅渲染給 manager | 7 個部門 | ~700 |
| 組織全景的「**經理每輪**」那一條 | 僅渲染給 manager | 7 個部門 | ~90 |
| 角色範圍整節（「CLAUDE.md 哪些不適用於部門」） | 僅渲染給部門 | manager | 1,473 |

**部門端每次 attach 省約 2.07KB／14.37KB ≈ 14.4%；manager 端省約 1.47KB ≈ 10.2%。**

**我不誇大這個數字**：經理的「14KB × 8 角色 × 每次 attach」若期待的是腰斬，這個做法達不到。
**達得到的做法都要刪規則，而那是你我都不接受的。** 若要更大的降幅，該動的是
brief 裡 `policy.md` 以外的那 17KB，不是這 14.4KB。

**computer use 那節要留一句 pointer**（不是整節）：
無 `computer_use` 能力的角色仍需知道「遇到這類工作以 `outcome=blocked` 回報並說明需 cockpit」，
那一句要留在渲染裡；其餘 16 行才是條件段。**這是本評估唯一的 pointer 建議，且它不減規則。**

```markdown
## 引用一個數字或欄位之前：它跟事實隔了幾層？

（形式由論文部提出，治理部裁定採納，2026-08-05）

引用任何欄位、指標或 gate 結論之前，先問三件事：**這個欄位是誰寫的**、
**什麼動作會讓它更新**、**那個動作與我關心的事實是不是同一件事**。
三個問題有一個答不出來，就去讀底層。

**為什麼是「數層數」而不是「不要相信」**：每多一層間接，多的是一個**必須自己去查的地方**，
不是一個不要相信的東西。**純粹的懷疑會癱瘓，數層數不會。**
一條讓人不敢動的規則等於沒有規則。

**誤判有四個方向，不是一個**：

1. **假的看起來真** —— 批量回填的時間戳（更新它的動作是「有人跑了腳本」，不是「有人核實過」）
2. **過時的看起來現行** —— 手填的 blocker 敘事欄位，沒有任何動作會讓它跟上現實
3. **真警告看起來像真問題** —— gate 沒壞、訊號是真的，但**粒度**與被問的事實不同
   （`INPUT_HASH_MISMATCH` 答的是「這個檔有沒有變」，被問的是「我的數字會不會變」）。
   **這一格最容易吃虧**：訊號可信，於是接受它的結論，而該降級的是 gate 不是被測物
4. **過期的外觀配當期的內容** —— `main.pdf` 的 mtime 早於 tex commit，但內容就是當前版

實例（都在 2026-08-05 同日發生）：`ops_snapshot` 讀 `sent_at` 而寫入端寫 `last_sent_at`，
於是「已送 alerts」恆為 0——**一個永遠回報 0 的指標，與一個真的是 0 的系統，畫面上一模一樣**；
`control_gate_registry` 的 `mode=shadow` 被讀成「這道 gate 沒退役」，但決定退役的是 `lifecycle`。

**修法方向**：欄位錯配就是錯配，**把它改對，不要並存**。加一個
`or v.get("last_sent_at")` 的 fallback 會讓錯的鍵永久留著，下一個人看到兩個鍵會以為兩個都合法。

## 擋一件事之前，先問它往壞的方向修正會怎樣

**若這個數字往壞的方向修正、結論只會更強 → 不必等，先做。**
只有當修正**可能翻轉結論**時，`blocked` 才有意義。

**下 `blocked` 的同時必須寫明「什麼證據出現時自動解除」**，否則嚴謹會變成拖延。
而**口徑修好的人要回頭解除自己下的 blocked**——上游不會替你收。

**誤差上界不等於誤差**：列出了上界，不代表你窮舉了偏誤的方向。
2026-08-05 實例：一份成本證據自帶「重複計算上界 60.1M」，據此擋下一個政策案；
實測重複量只有 4.07M（上界的 7%），而真正的失真方向與擔心的**相反**。
那個 `blocked` 只活了半小時，代價是延遲一輪。

**判為 stale／可疑，只改變舉證責任，不等於停擺**：回讀原始檔複核後即可照常引用。
**不得因為索引欄位陳舊，就把被索引的東西標成 blocked**——那是拿索引的缺陷去懲罰內容。
任何 block 都要在同一處寫出三條出路：**修復／寬限／裁決**。
```
