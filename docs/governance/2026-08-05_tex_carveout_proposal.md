# 提案：`paper/**/*.tex` carve-out 是否該由副檔名改為語意界線

- 立案：運營經理 D41 §一（`item_20260805T111052134793Z`），承 D38／D40
- 執行：治理部，2026-08-05T11:25Z
- **性質：提案，未落地。** 母本 `CLAUDE.md` 為老闆層治理文字，本部門未改動它，亦未改 `_core.py`。
- **結論：不建議放寬。** 但問題成立，代價可以幾乎歸零——見 §4。

## 1. 論文部指出的結構問題成立

現況 `scripts/org/_core.py:61-64`：

```
RESERVED_FILE_PATTERNS = (
    # CLAUDE.md: 論文寫作與方法論決策在主線程完成，禁止 background agent 寫 .tex
    "paper/**/*.tex",
)
```

論文部的批評是對的，而且值得逐字保留：**現在的分界線是副檔名，而副檔名不區分誰做了判斷。**
同一個 `.tex` 位元組，可能是一段新寫的方法論宣稱，也可能是把 `28/28` 改成 `27/28` 的錯字修正；
規則對兩者一視同仁。

實測後果也是真的：論文部拿到 `owned_paths=[paper/]`（`fc9f7e328`，「owning a parent of a
reserved zone is a carve-out, not a refusal」），但 v8 的六個已裁決 edit 全在 `main.tex`，
**一個都套不了**。經理已裁 A（主線程套用）作為出口，所以這件不是 blocker，是成本問題。

---

## 2. 經理問：什麼機械條件能證明「這是機械套用不是撰寫」？

經理提示 hash 綁定 + 逐字 FIND 錨點 + 不得新增段落。**我把它推完整，然後說明為什麼它仍然不夠。**

論文部的 `work/prg_v8_edit_instructions.md` 已經自發做到了其中大部分，可以拿它當實物驗收：

| 條件 | 機械可驗？ | v8 交接件是否已具備 |
|---|---|---|
| C1 目標檔 sha256 + byte 數綁定，不符即停 | 是 | 是（`8852326a…`／30408，明寫「不符即停，不要自行調整 FIND 去湊」） |
| C2 每個 FIND 字串在全檔**唯一命中** | 是 | 是（六筆逐一回讀確認唯一） |
| C3 等行數替換，不得新增／刪除段落 | 是 | 是（明寫「本批六筆都是等行數替換」） |
| C4 diff 僅落在被替換的 span 內 | 是 | 可由 applier 事後驗 |
| C5 round 證據夾不可變且被引用 | 是 | 是（`review_rounds/…/v8_review_20260805/` 四件） |
| C6 套用後驗證輸出**交回裁決者**判定收斂，不由套用者宣告 | 是 | 是（D40 §2） |

六條全部機械可驗，且已有實作先例。**如果問題是「這次的套用動作是不是機械的」，答案是肯定的，
而且已經證明得出來。**

### 但這六條證明的是錯的那一半

C1–C6 證明**套用**是機械的。它們**無法證明判斷是在該做判斷的地方做的**。

母本要保護的不是鍵盤動作，是**誰做了那個判斷**。而 v8 這六筆的判斷是**論文部**做的——
`latex_review.md` 的 MAJOR-1～4 是該部門的 review session 產出的，主線程沒有讀過那段散文。
於是「已裁決完畢」這個前提，把問題往前推了一格而沒有解決它：**裁決者本身就是那個
母本不允許獨自寫 `.tex` 的角色。**

放寬之後的實際形狀會是：同一個部門先裁決、再套用，主線程一次都不經手。
**規則沒有被違反，它是被拆成兩步繞過的。**

這正是我今天在另一案裡用的同一把尺（間接層數三問）：
「什麼動作會讓這個欄位更新／那個動作與我關心的事實是不是同一件事」。
C1–C6 更新的是「套用忠實度」，而母本關心的是「判斷歸屬」。**不是同一件事。**

---

## 3. 因此：不建議放寬（這是有效交付，不是為了交東西而放寬）

經理明示「如果結論是不該放寬，那也是有效交付」。**我的結論就是這個。**

副檔名界線很粗，但它粗在對的方向：它強制每一次 `.tex` 的散文變動都經過主線程一次。
主線程那一手就算多數時候只是照套，它仍然是**唯一一個母本指定的判斷落點**。
把它拿掉，換來的是吞吐，付出的是「論文散文從此可以完全不經主線程」——
而論文是本平台學術權威線的載體，那條線的護城河是研究誠實，不是交付速度。

**附帶理由（次要但不可忽略）**：語意界線不可機械判定。
「這是逐字套用還是撰寫」在檔案系統層面沒有 signal——
我們能驗的只有 C1–C6，而 §2 已經說明它們驗的是另一件事。
一條無法機械判定的界線寫進 `RESERVED_FILE_PATTERNS` 只會變成散文提醒，
依 CLAUDE.md 升級路徑那是 strike 1 層級，不該進機械層。

---

## 4. 真正該做的：不移動界線，降低過路費

論文部的痛點不是「規則錯」，是**主線程那一手很貴**——要人讀六段指示、手工比對 FIND、手工套用。

出路是把主線程那一手變成**一個指令**，而不是一次編輯 session：

**規格：`scripts/apply_paper_edits.py <instructions.md>`（實作面屬 platform_eng，本輪不派）**

1. 讀交接件的 front-matter 取得 target 檔、期望 sha256、byte 數 → 不符即 **exit 1**（C1）
2. 逐筆檢查 FIND 在全檔唯一 → 不唯一即 exit 1（C2）
3. 套用；套用後驗等行數（C3）與 diff span（C4）
4. 印出 diff 供主線程**在套用前確認**，`--apply` 才真的寫檔（預設 dry-run）
5. 完成後把驗證輸出寫回 round 證據夾，並產生一則給裁決部門的 `dept_send` 回覆（C6）

效果：主線程仍然是那個看過 diff 並按下確認的角色（母本要的東西**一個都沒少**），
但成本從「一次編輯 session」降到「讀一份 diff」。**論文部的六筆本來就已經是這個格式**——
交接件已經寫好了，缺的只是讀它的程式。

**這條路不需要改 `CLAUDE.md`、不需要改 `_core.py`、不需要老闆核准。**

---

## 5. 給經理的四句話

1. 論文部的批評成立：副檔名不區分誰做了判斷。**但這不代表界線該移動。**
2. 經理提示的機械條件我推完整了（C1–C6，六條全可驗，論文部已自發做到五條），
   **但它們證明的是「套用忠實」，不是「判斷歸屬」**——後者才是母本保護的東西。
3. 放寬後的實際形狀是：同一部門先裁決再套用，主線程一次不經手。
   規則不會被違反，會被拆成兩步繞過。
4. **不放寬，改降成本**：`apply_paper_edits.py`（§4），母本要的判斷落點一個都沒少，
   而論文部的痛點消失。這件不需要送老闆。

若經理仍要送老闆，本文件 §2 的 C1–C6 可直接當提案附件——**但請一併附上 §2 末段**，
不要只送「機械條件可以驗證」那一半。
