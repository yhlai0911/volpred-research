# 2026-07-16 CI run 29450374699：隔離 task pool 仍偷讀 live cluster state，另有 K1718 完成但未入 knowledge

## 現象

main Test Suite run `29450374699`（head `d4e004f03`）有三個失敗。cron wrapper manifest 漂移已由後續 commit `3e36eac3f` 修正；目前仍存活的是：

1. `test_research_reader_friendly_still_allows_general_companion` 的 temporary `NEXT_TASKS` / `CANDIDATES` 明明為空，K1120 卻被訊息 `cluster 'vix' already holds 3/2 pipeline slots` 擋掉。
2. K1718 實驗三件套、Codex review 與 task closure 都已進 main，knowledge ratchet 仍指出它是唯一 `results_without_knowledge`。

## 根因 A：hermetic source-tree leakage（Class P）

`refill()` 的 candidate/task source 可由測試或 recovery tool 重定向，但 `_ClusterBudget` 仍以無參數呼叫 `release_cluster_planner_state()` 與 `make_narrative_cluster_classifier()`；兩者預設讀 production `storage/reports/feed.json` 和 `storage/memory/knowledge.json`。

因此同一個 refill run 同時相信兩棵 storage tree。Live draft pressure 會污染 hermetic fixture，也會污染任何 redirected recovery run。

## 修正 A

`_ClusterBudget` 接受 `storage_dir`，`refill()` 明確傳入 `NEXT_TASKS.parent`；planner、classifier、candidate snapshot 與 task pool 現在共用同一 source root。既有 K1120 regression 加入 exact storage-binding assertion；`tests/test_refill_task_pool.py` 與 `scripts/tests/test_refill_cluster_budget.py` 同時覆蓋 hermetic 與 production gate 語義。

## 根因 B：實驗 closure 早於 knowledge coverage（Class E）

K1718 worktree merge 與 review PASS 後，task 被直接 complete；主線沒有執行 knowledge append。Task receipt 的「completed」因此比研究流程真正的 completion gate 更寬，實驗對 dedup/topic selection 完全不可見。

不能提高 ratchet baseline，也不能把 NULL 包裝成 PASS。

## 修正 B

主線用共享鎖 Python writer 新增唯一 K1718 entry，明列 `verdict=NULL`、0/6 Holm gate、reviewer/experiment provenance 與局限；同一份 record 增量同步 Mirror 與 Supabase。全量 `knowledge_unrecorded_ratchet` 與 K1259 provenance validator 同時歸零。

## 教訓

Hermetic 的單位是「一次 operation 讀到的整棵 source tree」，不是只 patch 最醒目的兩個 path。研究 task 的 `succeeded` 也不能代替 knowledge coverage；後者是 dedup 的資料前提。
