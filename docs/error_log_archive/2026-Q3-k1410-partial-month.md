# 2026 Q3 補充：K1410 partial-month 可重現性修復

## 2026-07-16 05:16 — 尾月 guard 隨日曆翻頁失效，已排除的單日月份重新污染重跑（Class O/P）

**現象**：K1410 在 2026-06-01 審查時已排除 TWII 當天唯一一筆資料，認證結果為 1997-08 至 2026-05、346 個月。2026-07-16 用同一份快取呼叫 `monthly_returns()`，卻得到 1997-08 至 2026-06、347 個月；程式已無法重現自己提交的結果檔。

**根因**：舊 guard 只問「最後觀測是否位於目前日曆月」。六月一日執行時答案為是，所以剔除；七月再跑時答案變成否，同一筆歷史資料便被當成完整六月。資料 bytes 沒變，判決只因牆上日曆翻頁而改變，屬於非 hermetic freshness 判斷。原修正只處理當下症狀，沒有覆蓋快取跨月重跑。

**修正**：尾月只有在至少 10 個交易觀測、最後觀測距日曆月末不超過 4 天，且不是目前日曆月時才保留。歷史單日或明顯提早截斷的尾月不會因時間流逝復活；目前月份仍保守等到下月才納入。新增 `tests/test_k1410_partial_month.py`，覆蓋跨月後單日尾月、完整歷史月、目前月份與完整歷史尾月。用原快取完整重跑後，除 `generated_at` 外結果必須與已認證 JSON 相同。

**教訓**：partial-month gate 不能只依賴「今天在哪個月」；快取的完整度判斷必須由資料本身決定，並用跨日曆邊界的 hermetic 測試驗證。同一份輸入隨重跑日期改結論，就是可重現性失敗。
